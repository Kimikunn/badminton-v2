# PRD: 风控验证引导与锁场重试窗口

## Goal

放票高峰（每日 09:00）场馆对 `createOrder` 触发图形验证，账号级拦截导致自动锁场全败，用户侧只收到一条"锁场失败、请手动预订"的通知，既不知情也无法配合。本任务把这段死路改成**用户可配合的闭环**：引导用户在小程序里过一次验证（服务端按会话免验证），系统在窗口期内自动重试直到锁到或超时，并让每次推送都有据可查。

## 背景（实测结论）

- 风控拦截发生在 `createOrder`，返回 429 / 403004；服务端无法自行过图形验证（腾讯防水墙 ticket 只能由微信客户端产生）。
- 服务端与小程序**共用同一 token-user**，因此在微信端过一次验证后，服务端后续请求按会话免验证。
- 未支付订单 5 分钟自动释放 —— 重试窗口必须短于用户可用的反应时间且不与其抢场冲突。

## In Scope

1. **风控重试窗口（引擎侧）**
   - `tryFulfill` 返回 `aborted: 'risk_control'` 时，引擎进入重试循环，而不是就地结束。
   - 先推「【需要过验证】」引导：说明去小程序走一遍预订拿验证、看到"验证成功"即可退出，无需真的下单；告知会自动重试。
   - 窗口期内按固定间隔重新拉取当日场次并**绕过 diff 直接评估该意图**（可订格子不产生 0→1 变化）。
   - 停止条件：锁到（成功推送由 `tryFulfill` 发出）／意图被停用或删除／token 失效（告警交主流程）／窗口超时（推【锁场失败】，说明重试未果、手动可订、回流照常）。
   - 同意图同日重入直接跳过，避免多轮触发叠加。
2. **锁场失败推送语义收敛**：风控中止不再由 `bookingLockService` 立刻推"立即手动预订"，统一由重试窗口接管，避免同一事件两条互相矛盾的通知。
3. **推送全量留痕**：引擎与锁场两条推送路径都写审计日志（成功/失败 + 标题 + 失败原因），用于排查"接口成功但用户没收到"。
4. **锁齐通知落库**：整段锁齐时按每个锁到的时段落通知记录（含订单号）。
5. **测试运行时隔离**：runtime 活文件（`gym-token`、`token-update-key`）路径每次调用实时解析，支持 `GYM_RUNTIME_DIR` 覆盖；测试 harness 指向临时目录，避免读到生产 token、避免并发测试互相污染。
6. **意图卡片排序（前端）**：按最近发生日从近到远排列，已过期（单次模式且日期已过）或 14 天内无匹配的意图沉底。

## Out of Scope

- 自动过图形验证（服务端无法完成，需人力配合，属已知天花板）。
- `createOrder` 真实放票时刻的完整成功路径实盘验证 —— 归 `08-29-auto-order`（需真实 slot 放票窗口，会下出真实订单）。
- 支付环节自动化。

## Acceptance Criteria

- [ ] AC1：`tryFulfill` 返回风控中止时，引擎推「需要过验证」引导，并在窗口期内自动重试；重试期间不重复推送引导。
- [ ] AC2：窗口内验证通过 → 自动锁到并推「已锁场」（复用既有成功推送），不再推失败。
- [ ] AC3：窗口超时仍未锁到 → 推「锁场失败」，文案不再让用户"立即手动预订"（风控路径）。
- [ ] AC4：意图被停用/删除、token 失效（401）时重试循环立即退出，不产生噪音推送。
- [ ] AC5：引擎与锁场两条推送路径均落 `push ok` / `push fail` 审计日志。
- [ ] AC6：整段锁齐时，每个锁到的时段写一条通知记录（成功/失败与推送结果一致）。
- [ ] AC7：`GYM_RUNTIME_DIR` 生效，`cd server && npm test` 全绿且不触碰真实 `server/runtime/`。
- [ ] AC8：意图列表按最近发生日排序，过期意图沉底且视觉弱化（既有 `opacity-50` 保留）。
- [ ] AC9：`CONTEXT.md` 的「放票风控」词条更新为新行为（引导验证 + 窗口重试），与代码一致。
- [ ] AC10：改动提交到 `master`，提交信息说明风控重试窗口与推送留痕。

## Risks / Notes

- 重试窗口长度与间隔是**经验参数**（4 分钟 / 12 秒）。窗口太短会浪费用户配合，太长会与"被抢"路径叠加噪音推送；若实测反馈不佳，调整 `rcRetryConfig` 即可，无需改结构。
- 引导文案假设"服务端与小程序共用会话免验证"，该假设来自实测；若场馆改为按请求校验，本机制退化为"窗口内多次尝试"（无害）。
